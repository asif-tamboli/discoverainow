Practical guide

Use AI in QA where review is cheap and leverage is high.

AI is most useful in testing when it expands coverage, accelerates drafts and challenges assumptions—while a tester still owns risk, evidence and release decisions.

Best starting points

1. Requirement interrogation

Ask AI to identify ambiguity, missing constraints, conflicting rules and testability problems. This is safer than asking it to invent the final test suite immediately because the reviewer can validate each question against the requirement.

2. Test-design expansion

Start from a human risk model, then use AI to propose negative, boundary, state-transition, concurrency and data-quality cases you may have missed.

3. Automation scaffolding

Use AI for boilerplate, page objects, API clients, data builders and first-pass tests. Review selectors, waits, assertions, test independence and cleanup before execution.

4. API and data validation

AI can help translate contracts and mapping rules into test ideas, but fabricated fields or endpoints are a common failure mode. Always anchor generation to the actual specification.

5. Defect triage

Ask the model to separate observations from hypotheses and produce the next diagnostic steps. Do not let it convert a plausible hypothesis into an asserted root cause.

Where AI should not be the final authority

  • Release sign-off
  • Security conclusions without evidence
  • Regulatory/compliance interpretation
  • Production incident root cause
  • Test coverage claims without traceability
Useful mental modelAI is a fast junior collaborator with enormous recall and uneven judgment. Give it structure, evidence and a reviewer.

A simple operating loop

  1. Human: define the requirement and highest risks.
  2. AI: expand cases and challenge assumptions.
  3. Human: remove irrelevant/hallucinated cases and prioritize.
  4. AI: draft automation or test data.
  5. Human + execution: verify against the actual system.
